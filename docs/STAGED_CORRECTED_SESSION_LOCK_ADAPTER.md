# Auth-bound TypeScript integration of the session-locked corrected preview

**Staging only.** The previous session-locked PostgreSQL function is now exercised through a separate private TypeScript entry point, `createTrustedSessionLockedCorrectedEconomicsPreview`. It accepts a `SessionBoundActiveSessionVerifier` backed by independent Supabase Auth verification and a private primary PostgreSQL connection; it never accepts an actor or session UUID from caller input. The public-facing selector shape stays restricted to `organizationId`, `sourceId`, `expectedDecisionSha256` and an opaque `session`.

The `createSessionBoundSupabaseVerifier` port now exposes `verifySessionBinding`, which only yields `userId` and `sessionId` **after** the exact token has passed the trusted Auth verifier AND the matching authoritative `auth.sessions` row probe. A compatibility `verifyActiveSession` method retains the original simple user-ID interface for other existing internal tools. The session-locked pricing adapter uses `verifySessionBinding` twice: first to send verified user/session IDs to `bm_intake_private.read_corrected_internal_preview_session_locked(org,actor,session,source,decision_sha)`, then after receiving the private projection to ensure neither identity nor session changed. Within the private SQL projection, the session row is locked for the duration of the database statement. The adapter enforces approved policy canonical SHA parity, exact source-derived service lines, and `preview-only` semantics before calculating confidential internal economics.

The older `createTrustedCorrectedEconomicsPreview` and four-parameter read path remain **solely for disposable staging tests**. The legacy TypeScript factory now refuses calls by default, requires the explicit literal `disposable-postgres-test-no-session-lock` in test fixtures, and **always refuses in `NODE_ENV=production` even with that acknowledgment**. New live integrations must use the session-locked factory; never depend on the legacy reader. Never publish either server-only factory through a customer API or return confidential cost, rate or margin data from it. This integration does not deploy a production endpoint, create sessions, or approve quote/send permissions.

**Mandatory testing:** `tests-web/trusted-corrected-economics-session-lock.test.mjs` verifies the five-parameter SQL selector, Auth-verifier type guards, in-flight session rotation/revocation, forbidden caller fields, forged policy hashes, and current-reviewer session proof. `ci/intake_corrected_session_lock_bridge.test.mjs` uses real ephemeral PostgreSQL with the existing corrected policy/evidence fixtures and synthetic Auth session rows. It requires a positive **69,000-cent** internal-only canonical-policy calculation through the locked SQL and verifies a committed session deletion immediately denies a subsequent preview. No test accepts a hash mismatch as a success.

**Unmet acceptance:** The Auth verifier uses simulated remote Auth in CI and the database is disposable. Real Supabase Auth, RLS/private Storage and two-user isolation tests, live revoked-session concurrency, secure operational deployment, file malware scanning, privacy/retention/legal/security signoff, final customer quote release and delivery remain unverified. This read-only path is not an approved customer-facing pricing or send service.

## Close the SQL-level legacy bypass

`db/staged_seal_legacy_corrected_preview.sql` revokes **direct `EXECUTE` by `service_role`** from the four-argument `read_corrected_internal_preview_inputs(org,actor,source,decision)` function. Unlike a `NODE_ENV` TypeScript guard, the database denial still applies when application code is misconfigured, a legacy integration bypasses the TypeScript factory, or a server has direct SQL access. The inner function stays private and callable by the trusted owner of the five-argument `SECURITY DEFINER` `read_corrected_internal_preview_session_locked` wrapper; direct browser execution remains denied.

The SQL permission seal is installed **after** earlier legacy regression fixtures and the actual session-locked TypeScript bridge in disposable CI. A new mandatory real PostgreSQL test proves the `service_role` direct four-argument call raises insufficient privilege, while an otherwise identical request with a valid synthetic Auth session succeeds through the five-argument locked wrapper. It also checks post-signout denial. The existing 24-check deployment preflight now requires **`internal_preview_indirect_only`**, i.e. that even `service_role` cannot directly call the unsafe inner entry point. A rollback-only fault injection re-grants EXECUTE and must cause the preflight to fail.

Do not run this as a live migration independently of reviewing function ownership, hardened `search_path`, current tenant membership, project Auth, and Item 3 migration order. No real Supabase schema was changed in CI. The legacy TypeScript test acknowledgment remains for tests executed **before** sealing; it is not a production escape hatch.
