# Item 4 — Pending correction candidates, still unapproved

This staging-only increment adds a **private, append-only correction candidate draft** to the existing quarantined source (revision 4). Each stored proposal now includes bounded, reasoned human edit actions (`add`, `remove`, `replace`) that PostgreSQL independently replays against the immutable original provider candidates, using original index order and deterministically sorted additions. A missing, duplicate, invalid or non-reproducing action fails before persistence. The correction is **not activated**, not a reviewed scope, not approved pricing, and cannot be quoted or sent.

`bm_intake_private.stage_correction_candidate_draft` requires current source-creator membership **before looking up the source**. It locks the original note and the existing immutable correction-hold receipt, verifies the request and hold fingerprints, immutable original/candidate hashes, and absence of any active scope. It independently validates 1–50 proposed candidates, exact allowed keys, source-exact UTF-16 excerpts (including supplementary Unicode), positive integral quantities, distinct service codes and canonical SHA-256; the proposal must differ from the original extraction.

The database stores the action list and an SQL-side JSONB digest in its immutable receipt. This is **not** the JavaScript `correctionSha256` fingerprint or evidence of a separately authenticated approval.

A single INSERT to `bm_intake_private.correction_candidate_drafts` stores the verified candidate list, human explanation, original hash, proposed hash, authenticated creator and database-produced receipt digest. Direct service-role/browser DML is denied; immutable trigger blocks UPDATE/DELETE, with a UNIQUE one-draft-per-source constraint that rejects retries and concurrent duplicates. The original source, model review, extraction audit, source revision 4 and NULL scope are all unchanged.

**Request binding:** The previously opaque quarantine `requestSha256` is now a versioned SQL JSONB SHA-256 commitment to the tenant/source UUIDs, original source and candidate digests, proposed candidate digest, and complete reasoned action list. Draft persistence independently replays edits and recomputes the same commitment; a modified reason, changed scope, or arbitrary hash fails closed. The original quarantine does not independently see the later submitted action list and can remain blocked if an inconsistent digest was supplied. The stored receipt proves source/candidate/action consistency, **not** an Auth signature, verified browser authorship, independent approver, ratecard approval, or activation. This SQL JSONB digest remains different from TypeScript `correctionSha256` and must not be used interchangeably. A future separately reviewed transaction must prove the full action lineage against the immutable provider extraction, then authorize activation and renewed human selection with a new approved policy. Existing TypeScript correction mutation/preflight remains disabled for revision 4; do not wire a public endpoint.

It tests private role grants, creator/foreign tenant/absent source denial, tampered spans, hidden pricing, duplicate services, unchanged proposals, forged hashes, missing reason, successful append-only source-bound draft, replay denial, ledger immutability and legacy scope rejection.
