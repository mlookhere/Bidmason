# Item 4 — Read-only corrected economics handoff (staging only)

`bm_intake_private.read_corrected_internal_preview_inputs` returns minimal, **source-derived internal preview inputs** and the **current two-actor-approved tenant company policy**. It does not compute or persist a price, create a customer quote, authorize a send, or change an intake source. Corrected records remain **revision 5** with `scope_review = NULL`.

The trusted server must derive the requesting commercial reviewer ID from freshly verified Auth, not a browser-provided actor parameter. SQL checks the current owner/operator reviewer **before private source lookup** and rechecks current memberships for the original creator and independent evidence reviewer. It requires a distinct third actor's immutable `approve-internal-draft` receipt. SQL locks the original source, private corrected-candidate and correction/activation/scope-review receipts, and currently approved policy head/version; it verifies selected-candidate provenance, deterministic replay of the original corrections, scope-selection fingerprint, current policy eligibility, and the internal commercial decision SHA. Policy revisions changed after review are rejected.

The returned JSONB has `state:"preview-only"`, `deliveryAuthorized:false`, a locked company `policy` object, an ordered `requested` array with only source-reviewed `serviceCode`, `units`, and optional `addonAccepted:true`, plus hashes for the source, reviewed candidates, policy and internal decision. Browser roles have no EXECUTE access. **The returned policy can include confidential company direct costs and must remain on a trusted server.** No customer, recipient, prices, send directive or document is returned.

A later Auth-bound server adapter can pass `policy` and `requested` to the already tested TypeScript `previewCompanyEconomics` for decimal-safe *internal* pricing and must independently verify that policy version/hash parity holds. Neither this staging SQL nor the existing pure calculator constitutes a deployable customer-quote path. Real Supabase Auth/RLS/private Storage, malware scanning, retention, signed release approvals, tax/legal/privacy/security checks and controlled delivery remain unverified.

`ci/db_intake_corrected_internal_preview_test.sql` is a required real disposable PostgreSQL test. It verifies reviewer-only tenant isolation, forged/missing request denial, private source-derived inputs and continued nonquotable revision 5.
## Trusted TypeScript integration adapter (staging)

`lib/trusted-corrected-economics-preview.ts` uses the existing server-only `ActiveSessionVerifier` and `PrivateIntakeDatabase` ports. It accepts ONLY an exact tenant UUID, source UUID, expected immutable internal decision SHA, and a nonempty, bounded (16 KiB maximum) primitive bearer string without whitespace or control characters. Rejected bearer selectors cannot invoke Auth or private SQL; this preflight is input hygiene, **not** authentication. It verifies the active reviewer immediately before the private SQL call, validates the complete nonquotable projection shape, independently snapshots the policy via the strict canonical serializer, compares the policy SHA and revision with the SQL-approved values, rebuilds strictly validated source-derived service lines, **reauthenticates after SQL returns**, then invokes the EXISTING `previewCompanyEconomics` deterministic calculator. The returned preview is internal-only and includes sensitive cost/margin information; it must never be forwarded to customer APIs. There is no write/send method.

The disposable corrected-scope fixture now activates its tenant policy from a **fixed JavaScript-canonical JSON byte string**, verified against the equivalent SQL JSONB policy before approval. The mandatory real PostgreSQL bridge asserts `canonicalCompanyPolicyText` exactly equals those UTF-8 bytes, checks the stored approved SHA, and **must complete a positive 69000-cent pricing preview** through the real SQL function and TypeScript calculator. A conditional pass on either parity rejection or success is not permitted. Other adversarial tests must continue rejecting forged, noncanonical or stale policy snapshots. Future production tenant policies must likewise be generated by `canonicalCompanyPolicyText` and approved by distinct verified actors.

`tests-web/trusted-corrected-economics-preview.test.mjs` validates canonical positive pricing, source/decision and tenant spoofing, policy price or hash tampering, unsupported fields/getters, and session revocation during reads. `ci/intake_corrected_preview_bridge.test.mjs` uses the actual disposable PostgreSQL private function, verifies source-derived selections, and proves parity enforcement and role isolation. Both are mandatory CI checks. This remains **not production Auth integration**.

## SQL envelope and disposable-only legacy entrypoint

The adapter reads the SQL `rows` array from an own, enumerable data
descriptor exactly once; inaccessible, hidden, accessor-backed, sparse or
decorated row evidence fails closed before pricing. When PostgreSQL metadata
is present, `rowCount` must be `1` and `command` must be `SELECT`.
Ordinary `pg` metadata and minimal isolated test results remain supported.
The negative cases assert that hostile getters are never executed.

The older four-argument preview factory has **no production authorization
path**. Its test-only constructor requires all three conditions:
`NODE_ENV` is not `production`, an exact
`disposable-postgres-test-no-session-lock` acknowledgment, and
`BIDMASON_CI_DISPOSABLE_POSTGRES=1`. Only isolated fixture test modules
activate this marker; no hosted service should set it. The marker and
nonproduction mode are rechecked at each invocation and after asynchronous
Auth and database boundaries, so a test-only adapter created earlier cannot
continue if its disposable execution context is withdrawn. This is a
test-harness safeguard, **not** a replacement for database authorization.
Live integrations use
`createTrustedSessionLockedCorrectedEconomicsPreview` and require independent
Auth, current `auth.sessions`, and the five-argument lock-protected SQL
function. Passing this CI gate is not approval to migrate, quote or send.
