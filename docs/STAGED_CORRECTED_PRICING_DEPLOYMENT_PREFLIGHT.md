# Read-only corrected-pricing deployment preflight

**Purpose.** Before applying any Item 4 staging SQL to a real tenant database, run `db/corrected_pricing_schema_preflight.sql` as a catalog-only `SELECT` on that project's primary Postgres connection. The query does not read customer data, user identities, Auth session contents, or private policy/ratecard records. It does not modify any schema, permission or data.

`psql -X -A -t -v ON_ERROR_STOP=1 -f db/corrected_pricing_schema_preflight.sql`

It returns one JSON object with the contract `bm-corrected-pricing-schema-preflight-v1`, count of checks, number passed, exact missing check names, and `staged_schema_ready`. Checks cover membership and source-table RLS (including **FORCE RLS** on source and idempotency requests), denial of **every browser direct read or write** of protected source, request and private commercial-receipt tables, service-only private schema and functions, source-bound activation/selection/commercial evidence tables, the active company policy head, Supabase's `auth.sessions` UUID column types and direct-read denial, verified **SECURITY DEFINER** and hardened `search_path` settings on the three private Auth/pricing functions, and correct service-only execute grants. All checks fail closed on missing objects. Missing objects or permissions must produce `staged_schema_ready:false`; they must never be silently treated as passing.

**Verified live observation (2026-10-19, read-only):** The connected BidMason Supabase project is available but returned **5/24** catalog checks passing and `staged_schema_ready:false`; **19 checks missing**. In particular, `public.bm_intake_sources` and `bm_intake_private` are not deployed. The expanded preflight did not modify any live object. The existing `bm_organizations` and `bm_memberships` tables have RLS enabled; `auth.sessions` includes `id` and `user_id`. A separately inspected `bm-evidence` Storage bucket is private with a file-size limit. No user data, tokens, secrets or project ref are recorded here. No schema or Auth records were modified.

It cannot establish actual signed Supabase Auth behavior, correct row-level isolation for two real tenant actors, private Storage policies, malware scanning, retention, legal/privacy/security approvals, session-revocation concurrency, corrected commercial release, or any customer quote/send permission.
