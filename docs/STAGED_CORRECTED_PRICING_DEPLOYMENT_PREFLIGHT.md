# Read-only corrected-pricing deployment preflight

**Purpose.** Before applying any Item 4 staging SQL to a real tenant database, run `db/corrected_pricing_schema_preflight.sql` as a catalog-only `SELECT` on that project's primary Postgres connection. The query does not read customer data, user identities, Auth session contents, or private policy/ratecard records. It does not modify any schema, permission or data.

`psql -X -A -t -v ON_ERROR_STOP=1 -f db/corrected_pricing_schema_preflight.sql`

It returns one JSON object with the contract `bm-corrected-pricing-schema-preflight-v1`, count of checks, number passed, exact missing check names, and `staged_schema_ready`. Checks cover membership and source-table RLS, absence of direct browser reads, service-only private schema and functions, source-bound activation/selection/commercial evidence tables, the active company policy head, Supabase's `auth.sessions` catalog shape, and correct grants for both the session probe and session-locked internal preview. Missing objects or permissions must produce `staged_schema_ready:false`; they must never be silently treated as passing.

**Verified live observation (2026-10-19, read-only):** The connected BidMason Supabase project is available but returned **3/14** catalog checks passing and `staged_schema_ready:false`. In particular, `public.bm_intake_sources` and `bm_intake_private` are not deployed. The existing `bm_organizations` and `bm_memberships` tables have RLS enabled; `auth.sessions` includes `id` and `user_id`. A separately inspected `bm-evidence` Storage bucket is private with a file-size limit. No user data, tokens, secrets or project ref are recorded here. No schema or Auth records were modified.

**Live security advisor:** An informational `RLS Enabled No Policy` finding for `public.bm_upload_quota` requires investigation of whether the quota table is deliberately service-only; do not create a permissive RLS policy merely to silence the advisor. [Supabase RLS advisor reference](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

**CI contract:** The same SQL is a **mandatory** late `intake-db` step after the complete private Item 4 schema, synthetic `auth.sessions`, and trusted pricing bridge tests have been installed. `ci/corrected_pricing_schema_preflight.test.mjs` requires **14/14 checks true**, verifies no missing checks, and asserts the report never claims production or delivery authorization. The live 3/14 result is expected **until the prerequisites are properly migrated**; it is NOT overridden or counted green by a disposable CI run.

**Not production approval:** A passing schema preflight confirms catalog presence and privilege configuration only. It cannot establish actual signed Supabase Auth behavior, correct row-level isolation for two real tenant actors, private Storage policies, malware scanning, retention, legal/privacy/security approvals, session-revocation concurrency, corrected commercial release, or any customer quote/send permission. PR #12 (tenant RLS) remains an unmerged dependency of Item 4 draft PR #13. Do not apply schema changes or remove CI checks just to turn this report green.
