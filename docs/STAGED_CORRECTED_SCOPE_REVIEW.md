This **staging-only** increment implements a **new, append-only, private human scope selection draft** for correction revision 5. It requires the original creator's current tenant membership, independently accepted/activated correction evidence and the **CURRENT** two-person-approved company policy. The source still remains **revision 5**, `scope_review` stays `NULL`, and legacy quote readers reject this state. A successful draft is not a proposal, permission to bill, or authorization to deliver anything.

The SQL revalidates the original source SHA and immutable provider extraction audit, independently replayed reasoned correction actions, versioned request/draft/evidence/activation fingerprints, and activation marker. The currently active approved policy head and immutable policy version are row-locked to prevent an approval transition during the selection transaction. Only candidate indices and explicit add-on acknowledgements eligible under that actual policy are accepted: missing/pending/excluded services, unsigned or mismatching policy revision/sha, duplicate selections or unacknowledged optional add-ons are denied.

The new table `bm_intake_private.corrected_scope_review_drafts` is single-write per organization+source with private revocation of direct service/client DML and immutable update/delete trigger. It stores original source/corrected-candidate/activation and policy version hashes, selected indices, accepted add-on codes, the existing reviewed-selection fingerprint, and an additional database-produced receipt fingerprint. No direct client or service table reads. The separate SQL function `review_corrected_scope_pending` requires a freshly verified Auth actor supplied only by the trusted server. No public application endpoint has been wired.
